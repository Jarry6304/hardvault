# hardvault CLI 設計筆記

本文件記錄 `hardvault` Rust CLI 的內部設計，主要目的：

1. 讓 codegen 產出與 C# `GeneratedSecretsProvider` **byte 格式完全一致**
2. 作為實作 P3 階段（rust 端 CLI）的契約文件
3. 讓貢獻者理解每個設計決策的理由

---

## CLI 子命令

| 命令 | 用途 | 讀取 ENV |
|---|---|---|
| `hardvault build` | 讀 `secrets.toml` → 產 `.cs` + `.json` | `HARDVAULT_MASTER_KEY`（必要） |
| `hardvault keygen` | 產生 32 bytes 隨機 → base64 | — |
| `hardvault verify` | 驗證 `secrets.toml` 與已產 `.cs` 一致 | `HARDVAULT_MASTER_KEY`（必要） |
| `hardvault rotate` | 用新金鑰重加密所有密文 | `HARDVAULT_MASTER_KEY`（舊）+ `--new-key-env` |

### `hardvault build` 旗標

```
--input <PATH>        預設 secrets.toml
--out-cs <PATH>       預設 Infrastructure/Security/GeneratedSecrets.cs
--out-json <PATH>     預設 appsettings.json
--namespace <NAME>    預設 Hardvault.Security
--key-env <NAME>      預設 HARDVAULT_MASTER_KEY（dev/staging/prod 切換用）
```

**絕對不提供** `--master-key <KEY>` 旗標 — CLI 旗標會出現在：
- shell history（`bash_history`、PowerShell history）
- 父 process 列表（`ps aux`、Task Manager）
- CI log（GitHub Actions、Azure Pipelines）
- crash dump

金鑰只能從環境變數讀取。

## 加密格式

每筆密文 byte layout：

```
┌────────────┬──────────────────┬────────────┐
│  nonce 12  │  ciphertext N    │   tag 16   │
└────────────┴──────────────────┴────────────┘
   0..12         12..N+12         N+12..N+28
```

- 演算法：AES-256-GCM
- nonce：每次加密**重新產生**（`OsRng` / `getrandom`）
- tag：固定 16 bytes
- 金鑰：`HARDVAULT_MASTER_KEY` env，base64 解碼後必須 32 bytes（256-bit）

> ⚠ C# 端 `GeneratedSecretsProvider.Decrypt` 必須照同樣 layout 拆解 — 變更格式時兩邊要一起改，並升 codegen schema 版本號。

## TOML schema

```toml
[secrets]   # → AES-256-GCM 加密
KEY1 = "value1"
KEY2 = "value2"

[config]    # → 明文（UTF-8 bytes）燒入
KEY3 = "value3"
KEY4 = "value4"
```

驗證規則：
- 兩個區段都可省略，但至少一個要有內容
- KEY 命名建議 `SCREAMING_SNAKE_CASE`，需符合 `[A-Z][A-Z0-9_]*`
- 同名 KEY 不可同時出現在 `[secrets]` 與 `[config]`（build 時報錯）
- TOML 註解（`#`）**不**進產出檔（避免洩漏 hint）

## 產出檔案

### `appsettings.json`（契約檔，**進** Git）

```json
{
  "Hardvault": {
    "Secrets": ["LINE_TOKEN", "DB_PASSWORD"],
    "Config":  ["SCAN_CRON",  "PAGE_SIZE"]
  }
}
```

只有 KEY 清單，沒有 VALUE。團隊成員看 PR 就知道有哪些設定需要同步。

### `GeneratedSecrets.cs`（密文檔，**不**進 Git）

```csharp
// <auto-generated by hardvault {version} at {timestamp_utc}>
// 不要手動編輯。重新產生：hardvault build
using System.Collections.Generic;

namespace Hardvault.Security;

internal static class GeneratedSecrets
{
    internal readonly record struct Entry(bool Encrypted, byte[] Data);

    internal static readonly IReadOnlyDictionary<string, Entry> Entries =
        new Dictionary<string, Entry>
        {
            ["LINE_TOKEN"]  = new(true,  new byte[] { 0x1a, 0x2b, /* ... */ }),
            ["DB_PASSWORD"] = new(true,  new byte[] { 0xde, 0xad, /* ... */ }),
            ["SCAN_CRON"]   = new(false, new byte[] { /* "0 0 8 * * *" UTF-8 */ }),
            ["PAGE_SIZE"]   = new(false, new byte[] { /* "50" UTF-8 */ }),
        };
}
```

## Release profile

```toml
[profile.release]
opt-level     = 3
lto           = "fat"
codegen-units = 1
panic         = "abort"
strip         = "symbols"
```

效果：
- `strip` 移除 debug symbols 與 panic backtrace 字串
- `lto = fat` 跨 crate 內聯 + dead code elimination
- `panic = abort` 進一步縮小 binary
- 預期最終 binary 約 1–3 MB，符號表幾乎清空

```

    ├── integration.rs   # build / verify / keygen e2e
    └── roundtrip.rs     # Rust 加密 → 模擬 C# 解密 → 比對
```

## 測試策略

1. **單元測試**（`#[cfg(test)]` in-module）：每個模組獨立驗證
2. **整合測試**（`tests/`）：呼叫 binary、比對輸出
3. **Roundtrip 測試**：Rust 加密 → 用 `aes-gcm` crate 自己解 → 比對明文（驗證 byte layout 與 C# 一致的關鍵）
4. **CI matrix**：GitHub Actions windows / ubuntu / macos × stable / beta

## 安全考量

- ❌ **絕不** print 解密後的明文，即使 `--verbose`
- ❌ **絕不** 接受 `--master-key <KEY>` 旗標
- ✅ 讀取 ENV 後立即用 `zeroize::Zeroizing<Vec<u8>>` 包裝
- ✅ tag 驗證失敗時錯誤訊息**不**洩漏部分明文或 nonce
- ✅ TOML 中的 `# 註解` 不會出現在產出 `.cs` 內
- ✅ `secrets.toml` 解析後立即 zeroize 原始 buffer

---

## 已知限制

- 不支援 secret 動態更新（設計選擇，非 bug）
- 不支援多 profile（dev / staging / prod 用不同 `secrets.toml` + 不同 `HARDVAULT_MASTER_KEY` 即可）
- 不支援巢狀 secret（appsettings 巢狀仍可在 C# 端 wrap）
- `hardvault rotate` 需要原 `secrets.toml`（密文無法直接 rotate，因為 nonce 也要重產）
